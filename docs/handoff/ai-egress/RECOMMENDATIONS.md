## 0. 一句话

**只在需要出网的那个应用里，显式指向本机 loopback 上的 SOCKS5 / HTTP 代理端口；操作系统的代理、DNS、TUN、路由表、防火墙一律保持原样。** 做不到精确回滚的方案就不要上。

---

## 1. 推荐做法：应用级显式代理（唯一默认方案）

### 1.1 边界

| 允许 | 不允许（本文不提供，也不建议） |
|---|---|
| 在**单个应用**的配置或环境变量里显式写 `127.0.0.1` 上的 SOCKS5 / HTTP 端口 | 改动操作系统的代理设置 |
| 只在**当前进程 / 当前终端会话**内导出环境变量 | 改动 DNS 服务器、hosts、DoH/DoT 设置 |
| 用客户端自带的「仅本地监听」混合端口 | 启用 TUN / tun2socks / 虚拟网卡 |
| 出问题时停掉这个应用的代理设置 | 改路由表、改防火墙规则、装内核驱动 |

**本方案不修改系统代理。** 这不是措辞谨慎，是硬约束：系统代理是全局状态，出错时影响面是整台机器，而且很多客户端在退出时不会把它改回去。

### 1.2 PAC 的定位

PAC（代理自动配置脚本）**不作为默认方案**。它的常见用法是「把 PAC 地址填进操作系统的自动代理配置」，那等于改全局状态，违反 1.1 的边界。

只有当**目标应用自身**支持直接加载 PAC、且该设置的作用域仅限该应用时，才可以考虑；即便如此也要先确认「关掉这个设置」能让该应用恢复原状。**未核验**：本轮未逐个核实常见客户端是否支持应用级 PAC，不要据此下结论。

### 1.3 落地形态（模板，按需替换尖括号占位）

监听端：由本地代理客户端在 `127.0.0.1` 上监听一个端口，例如 `127.0.0.1:1080`（SOCKS5）或 `127.0.0.1:1081`（HTTP）。**不要监听 `0.0.0.0`**，否则同网段其他机器可以直接借道。

使用端（每种都只影响自己，互不牵连）：

```text
# 仅当前终端会话；关掉窗口即失效
set HTTPS_PROXY=http://127.0.0.1:1081      # Windows cmd
$env:HTTPS_PROXY = "http://127.0.0.1:1081"  # PowerShell
export HTTPS_PROXY=http://127.0.0.1:1081    # bash/zsh

# 单条命令级
curl --proxy socks5h://127.0.0.1:1080 <目标地址>

# Git：作用域写 --local，留在这个仓库里，不污染全局
git config --local http.proxy socks5h://127.0.0.1:1080
```

要点：
- 优先用 `socks5h`（让代理端做 DNS 解析），避免本机 DNS 泄漏目标域名；但这**只影响这一个应用**，不动系统 DNS。
- 环境变量只在需要出网的那一个进程/会话里设，不要写进系统环境变量、不要写进 shell 启动脚本。
- 记录你改了哪几处（见第 2 节的清单），否则回滚时必定漏。

## 2. 回滚：精确恢复，失败就停用，绝不降级

### 2.1 开工前先把原状抄下来

改之前，逐项记录**原值**（包括「原本就没有设置」这个事实本身）：

| 项 | 记什么 |
|---|---|
| 环境变量 | `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` 的原值，或「原本未设置」 |
| 应用配置 | 改动前的原文件副本（放在你自己的临时目录，不要进仓库） |
| Git 配置 | `http.proxy` 的原值与**作用域**（local / global / system），或「原本没有这一项」 |
| 进程状态 | 代理客户端原本是否在跑、跑的是哪份配置 |

### 2.2 回滚动作

1. **原本没有的项就删掉，不要设成空字符串。** 空值和未设置在很多客户端里行为不同。
2. **原本有值的项，改回原值**，并且改回原来的作用域。
3. 代理客户端**原本没在跑**，就停掉它；原本在跑，恢复到原来那份配置再启动。
4. 逐项复核一遍，确认每一项都回到了 2.1 记录的状态。

### 2.3 失败时怎么办（这一条是红线）

**回滚失败时，不允许让流量退回直连。**

理由：直连在这个场景里不是「安全的默认值」。它会把真实出口地址直接暴露给目标服务，而这恰恰是引入代理要避免的事情；更糟的是它通常**静默**发生，使用者以为还在走代理。

正确处理：

1. **停用新路径**——把应用的代理设置移除或把应用停掉，宁可这个应用暂时不能出网。
2. **明确报告**——写清楚哪一项没能恢复、当前处于什么状态、需要人做什么。
3. 在人工确认之前，不要再自动重试、不要自动切换到别的出口。

> 一句话：**fail-closed，不是 fail-open。** 恢复不了就断掉，而不是「先连上再说」。

## 3. 链路：第一跳 ≠ 最终出口

这是最容易被误解、也最容易导致错误承诺的一点。

```text
你的应用 → 127.0.0.1 本地监听端口 → [第一跳：Shadowsocks 服务端] → …（可能还有若干跳）… → [最终出口：某个 ISP 的地址] → 目标网站
```

- **第一跳**是你的客户端直接连上的那台服务器。它决定「你的流量先交给谁」。
- **最终出口**是目标网站实际看到的来源地址。它由链路末端决定，**未必**等于第一跳。
- 如果链路中间还有中转、负载均衡或再出站，**最终出口可能随时间变化**，也可能在多个地址之间轮换。

因此，下面这些话**一律不能说**：

| 不能承诺 | 为什么 |
|---|---|
| 「这个出口 IP 是干净的」 | IP 信誉由各家目标服务自行判定，会动态变化，你无法核验，也无法代它们承诺 |
| 「换了出口账号就不会被风控」 | 账号信任度取决于对方的完整风控模型，出口地址只是其中一个因子 |
| 「用了这条链路就能恢复之前的访问能力」 | 能力是否恢复由对方决定；换链路既可能无效，也可能触发新的风控 |
| 「固定 ISP 出口 = 住宅 IP = 安全」 | 「固定」只说明地址不常变，不说明它的历史记录和分类结果 |

可以说的是事实描述：这条链路的第一跳在哪、最终出口当前解析到哪、是否稳定。**这些也要实测，不要照抄服务商的宣传。**

## 5. 交付物边界：只交模板与工具，不交数据

**不打包、不上传、不提交**下列任何内容：

- 真实的客户端配置文件（即使你觉得已经删干净了）
- 任何凭据：密码、`TunnelSecret` 之类的密钥字段、API key、cookie、token
- 订阅链接（订阅链接本身就是长期凭据）
- 节点列表、服务器地址、端口、备注名
- 含上述内容的截图、日志、抓包文件

**可以交付**的只有两样：

1. 本目录下的这两份文档（纯模板与说明，占位符用尖括号写）；
2. `tools/redact_scan.py` —— 一个**只读、离线、不联网**的本地脱敏扫描器。

### 5.1 出包前自查

```text
py -3 tools/redact_scan.py --dir <你要外发的目录>
```

退出码的含义：

| 码 | 含义 | 该怎么办 |
|---|---|---|
| 0 | clean：未命中已知模式，且没有解析不了的东西 | 仍需人工复核（见下） |
| 1 | finding：命中了已知模式 | 按输出的规则 id 与行号逐条处理 |
| 3 | unknown：存在无法可靠解析的内容 | **这份报告不可信**，必须人工看过那些内容 |
| 2 | 用法错误 | 检查参数 |

默认输出**只有**规则 id、类别、命中次数、行号和文件扩展名——**不打印文件名、路径、原文片段或匹配值**，因为文件名本身常常就是敏感信息，而把匹配值打到终端等于又泄漏一次。

### 5.2 「零命中」不等于「安全」

扫描器只做正则与有限的结构化匹配。它抓不到：被拆分拼接的秘密、自定义字段名、语义上敏感但形态普通的文本、以及它解不开的任何编码。**退出码 0 只表示「未命中已知模式」。** 外发前的人工复核不能省。
