# 0001 所有改动走 分支 → 工作副本 → 审查 → 合入

**情况（2026-09-28 盘点）**：73 个分支、73 个工作副本、0 个版本标签；9/25 的离线集成分支 zex 一次带了 34 个提交，其中一行关键代码是在解冲突时丢掉的（F1）；几次"修好了"没有绑定具体提交，事后说不清跑的是哪个版本。

**决定**：
- 每件事一个分支、一个工作副本（`.wt/`），主目录只放 main。
- 审查结论必须写 `PASS @<提交号>`；作者不审自己。
- 人工分支只快进合入；`task/*` 施工分支由 `bus_build merge` 在临时副本合并 + 门禁后快进 main。
- 每次合入写 CHANGELOG（含回滚方法），每批打版本标签。
- 细则见 [WORKFLOW.md](../WORKFLOW.md)。

**为什么**：多个 Agent 同时改一个仓库，没有隔离就一定互相覆盖；审查不绑提交号，就可能"审的是 A、合的是 B"（`bus_build_safety` 已用测试覆盖这种情况）。

**放弃了什么**：速度。一个小改动也要开分支、等审查。紧急止血允许"先合后审，24 小时内补审"。

**回滚**：这是流程约定，不涉及代码。
