# 0020 本机首次施工仓库绑定

日期：2026-10-14。状态：按本人继续可靠性发布准备的授权实现，代码待独立审查；不代表已配置任何生产项目。

## 问题

ADR 0017 要求新 build 有明确的项目仓库绑定。已有 create_project 默认 repo_dir 为空，而普通 update_project 拒绝该字段。这项拒绝是既有权限边界，不能通过放宽 HTTP/MCP 通用 patch 修复。缺少可检查的首次配置入口，会导致未绑定项目在升级后只能拒绝施工。

## 决定

新增 `bus_repo_binding.py` 和本机 CLI `scripts/bind_project_repo.py`。不暴露 HTTP/MCP 端点，不自动迁移、不扫描推断、不启动施工。必须显式给出 projects 实例目录、项目标识和已存在的 Git 工作树根目录。

默认 preview 不写盘，也不创建互斥文件。输出目标、当前配置摘要、Git 根/git_dir/HEAD 和 plan_id。plan_id 仅是并发校验摘要，不是身份凭据，也不是防篡改签名；本机操作者权限来自操作系统和上层真实授权。

apply 必须携带 preview 的 plan_id、精确项目确认、操作者和理由。在与普通项目更新相同的 `.project.mutex` 中重新读取记录、重新核对 Git 身份与 HEAD、核对摘要，随后一次原子替换同时写入 repo_dir 和 repo_binding_receipt。变化则拒绝，不覆盖用户修改。重复同一计划且已绑定目标一致时返回 already_applied，不重复审计。未发生变更时不新建审计记录。

v1 仅允许空绑定到明确目标；已经绑定相同目标则 no-op，绑定到另一目标一律拒绝，重绑定与解除必须另立迁移任务并核对在途施工。合法 Git worktree 的 `.git` 文件支持；子目录、无提交仓库、非 Git 目录和相对路径拒绝。清除继承的 Git 定位/配置环境覆盖，验证过程不执行 hooks、不初始化仓库、不联网。

## 限制与取舍

这是可信单用户机器的受控管理工具，不是恶意进程对抗沙箱。不能阻止拥有相同文件权限的进程直接编辑项目文件或替换仓库。需要调用者和项目正常写入者遵守同一锁；审批摘要不能独立证明用户真实同意。

预演不会创建代码或任务。apply 只写指定项目的 repo_dir 和单条首次绑定回执，不改 peers、来源、历史决策或其他项目。保持原通用 patch 拒绝 repo_dir 的测试。日志/计划包含本机路径，只留本机私有目录。

## 验收

临时项目和 Git 仓库：preview 零写入；明确确认必需；项目/HEAD 改变后旧计划拒绝；并发重复只提交一次；写失败保留原文件；已有绑定不改指向；正常字段保留；Git 环境覆盖不误导根目录；关联 worktree 支持；CLI 默认只读及显式 apply；普通项目接口仍拒绝权限字段。

## 上线与回退

程序可先上线但不自动绑定任何未知项目。已有合法绑定不变；未绑定项目明确报错，非施工行为保持兼容。具体项目绑定另需核实真实路径与适用授权，使用本工具预演后确认。

代码回退可 revert 本项提交，已写入绑定与回执必须保留，旧版本会忽略新增回执字段。撤销实例绑定不是代码回退：须先停止相关施工并核对回执及最新项目状态，只恢复目标字段，不能用整份旧 project.json 覆盖并发产生的其他修改。

## 操作

先运行 `python -X utf8 scripts/bind_project_repo.py --help`。在本人授权的目标实例上填入明确目录、标识及仓库，用无 `--apply` 的调用获取预演；确认结果后携带 `--apply --expected <plan_id> --confirm-project <slug> --actor <operator> --reason <reason>` 执行。不要将 `<...>` 当作可直接执行的路径或授权。
