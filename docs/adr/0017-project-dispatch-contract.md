# 0017 项目身份贯穿派发入口

日期：2026-10-13。状态：已采纳为实施方向（本人授权）；实现、审查和部署分别记录。

## 当时的情况

bus_core.dispatch支持project，但bus_mcp.bus_dispatch及bus_tool缺失透传；归属推断和post回落当前项目会将跨项目工作记错。

## 决定

project显式参数贯穿MCP、转发、核心及task/meta。显式项目不得被当前会话覆盖，归属来源可追溯。来源项目、负责验收项目与执行仓库是不同概念。

新施工在任何worktree/inbox副作用前校验项目存在、项目绑定仓库及调用方目标一致。缺少可确认归属则拒绝，返回不带敏感内容的修复提示；不自动新建项目或初始化默认仓库。保留旧非施工调用兼容，推断不升级为授权。父任务可作为结构化归属证据，但不能默许冲突。

MCP、CLI、HTTP及插件调用链的字段不可各自漂移。新字段采用可选参数保证非施工调用兼容；确实涉及安全收紧的旧调用必须有迁移说明。

## 为什么与放弃了什么

先补接口契约而非增加分类模型。放弃缺字段仍静默开始施工的便利；旧任务不靠标题猜测批量搬家。

## 验收

跨入口透传、显式B覆盖会话A、非法项目/路径逃逸、仓库不匹配、未知施工零副作用、父任务关联、post不移动已绑定任务。测试均用临时项目和仓库。

## 回滚

revert独立提交，保留新增meta字段；不迁移旧任务。向旧客户端说明显式project与repo_dir的正确传法。
