# 0002 插件 = 文件夹 + 清单 + 独立进程，只走 HTTP

**情况**：旧的外部源接入（`adapters/daily_assistant.py`）是个独立脚本，写死了工作台地址，直接往 Leader 指令队列里塞；首轮运行可能一次导入约 85 条历史项；没有开关、没有日志、崩了没人知道。你要求工作台"可插拔、可热插拔、不和其它项目硬耦合"。

**决定**：
- 插件 = `plugins/<id>/plugin.json` + 代码。清单带 `api: workbench-plugin/1`，接口不兼容时升版本号、明确拒绝旧插件。
- 工作台把插件当**独立子进程**启动，注入地址/配置/数据目录环境变量；插件只调 HTTP 接口。
- 开关和配置存本机 `plugins.local.json`，即时生效，不重启工作台。
- 只开放三类：`source` 数据源（送收件箱）、`notifier` 通知（读事件）、`panel` 页面。
- 数据源只能"召回"，必须经收件箱由本人确认；首次启用只打基线。

**为什么**（参考了三个成熟系统）：
- VS Code：扩展跑在独立进程，一个扩展崩了编辑器不受影响。
- Home Assistant：每个集成一个清单，可以单独重载，不用重启整个系统。
- Obsidian：开关即时生效；插件带最低版本号。
- 反面：KDE 4、Eclipse OSGi、旧 Firefox 扩展都死在"什么都能插、插件互相依赖"。所以只开三个固定口子。

**放弃了什么**：插件不能直接改主界面、不能 import 核心代码——功能上受限，但换来核心可以随便重构。

**回滚**：`git revert --no-commit 0034936..d7b6d12`（事件、插件、收件箱、反馈四块互相 import，ADR 0002/0003/0004 只能一起撤）。只想停用插件而不动代码：`py -3 bus_web.py --no-plugins`，或在界面上关掉开关。旧 adapter 在标签 `archive/pre-cleanup-20260928` 里可找回。
