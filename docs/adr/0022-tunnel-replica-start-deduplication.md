# 0022 隧道副本启动按真实进程身份去重

日期：2026-10-14。状态：候选实施，独立审查与上线分别记录。

## 情况

守护同时存在副本进程检查和公网健康检查，两条失败路径都可调用 `start_replica`。旧函数不查已有实例就启动；公网暂时不通或 PID 文件丢失会反复创建同配置进程。临时夹具已复现连续与并发调用重复启动。

## 决定

启动和登记在同一跨进程互斥锁下完成。启动前只读查询进程，按可执行文件完整路径、由本启动器产生的精确参数形状、配置文件路径匹配，不能只认进程名或裸 PID。

同配置实例已经存在时复用，不追加启动。旧 PID 文件丢失/损坏时从真实进程恢复登记。进程身份读取失败或不完整时停止自动启动，明确报告未知；不要把未知当作进程已死。新进程已启动但登记失败，后续查询也不能继续重复创建。

已有多个匹配副本时保留并报告，不在这次修复中批量杀进程或清理隧道。不同配置、Windows 系统服务及非本启动器参数形状不接管。恢复公网健康不等于需要新建进程。

## 边界

这是可信 Windows 单用户部署中的资源保护，不是进程访问控制。CIM 读取权限不足时可能需要人工检查；不能通过放宽身份匹配或升级全局权限强行恢复。进程状态可变化，判定只反映观测时点。未访问真实隧道、未读取/回显配置文件内容。

## 验证与回滚

`tests/test_guard_replica_singleton_20261014.py` 用虚构进程、配置文件和 spawn 检查重复/并发请求、多个旧副本、未知状态、PID 损坏、路径与参数匹配。Windows 原生参数拆分另有无进程启动的测试。

回退在独立分支撤销对应提交并经验证后部署。既有 PID 数字文件格式保持可读；不自动清理旧进程，不改配置或账号。部署后验证需核对原有进程数量和实际守护日志，代码测试不等于真实网络验收。
