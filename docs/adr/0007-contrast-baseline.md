# 0007 文字对比度底线：WCAG AA 4.5:1，用测试守住

**情况**：用浏览器算实际颜色后发现，亮色主题的次要文字色 `--faint` 对比度只有 2.2–2.5:1（标准是 4.5:1，大字也要 3:1）。时间戳、提示、文件路径、epoch 这些 11–12px 的小字都用它，截图里"灰得看不清"的根源就在这。暖沙主题同样问题（2.3:1），强调色和警告色也略低；暗色 / 石墨的 `--faint` 在 3.4–4.3 之间。只有高对比主题全部达标。

**决定**：
1. 各主题的正文类颜色（text / muted / faint / warn / danger / accent）在 bg、surface、surface-2 三种背景上的**最差值**都要 ≥ 4.5:1；主按钮文字对强调色也 ≥ 4.5:1。
2. 调色方法：保持色相，只沿"朝正文色"方向插值，取**刚好达标**的那一点（faint 取 4.6、muted 取 5.5，保留 muted 比 faint 深一档的层次）。数值由脚本算出，不靠目测。
3. 状态色（ok / info / violet，及 warn / danger / accent）放在各自的浅底 `--x-soft` 上也 ≥ 4.5:1（fable2 8c1c 退回补齐：暖沙 `--ok` 原 3.82、`--violet` 4.40，高对比 `--accent` 在浅底上 4.29）。
4. 状态不用半透明表达：离线头像、不可用的 Agent 选项、空模型组、暗淡筛选项原来用 `opacity:.55–.7`，把文字压到 1.6–3.7:1。改用灰度、虚线边框、浅底、次要文字色。
5a. 键盘焦点环用实色 `--focus-ring`（2px），与装饰用的强调色解耦：预设主题下它就是 `--accent`（守卫保证 ≥ 4.5:1，焦点环 ≥ 3:1，WCAG 1.4.11）；用户保存了对底色 < 3:1 的自定义强调色（设置页只提示不拦截）时，`prefs.focusRing` 回退为 `--text`；判断取 bg / surface / surface-2 / surface-3 四种底色的最差值（fable2 13b7 实测 #8c8c8c 对 bg、surface 过 3，但在 hub 筛选栏的 surface-2 上只有 2.95）。理由：强调色是审美选择，可以降级；焦点可见性是功能，不能跟着降级（fable2 a7ad 指出原写法下 #ffdd00 的焦点环只有 1.35:1）。原来 65% 半透明在亮色只有 2.94、暖沙 2.64；顶栏品牌标题的 1px 浅灰虚线只有 1.7–1.9。`scripts/ui_audit.py` 每页真按 30 次 Tab 检查。
5. 约定：`--surface-3`（代码块、hover 底）上不放 `--faint` 文字——faint 在 surface-3 上各主题只有 4.0–4.4；再加深 faint 会让它和 muted 分不开。真实页面扫描未发现此用法。
6. `tests/smoke_contrast_tokens.mjs` 解析 tokens.css 逐主题计算，以后谁改颜色掉到标准以下，测试直接失败。同时检查 prefs.js 的预设强调色与 tokens.css 一致。

**为什么**：画像里偏好低认知负担。看不清的字等于没写，还会让人凑近屏幕、放大页面。对比度是少数有客观标准的视觉问题，适合用测试固定下来。

**代价**：亮色主题的灰字明显变深（新的 faint ≈ 旧的 muted），整体"更实"、少了一点轻盈感。层次改由字号 / 字重 / 位置承担更多。暖沙的强调色从 `#a5682a` 变为 `#8e5b27`（更深的棕）。

**放弃了什么**：AAA（7:1）——次要文字会和正文几乎无差别，层次消失。只改 faint 不改 muted——亮色主题下 muted 在 surface-2 上是 4.48，也不达标，而且 faint 达标后会比 muted 还深。

**回滚**：`git revert <合入提交>`；想单独放宽某个主题，改 tokens.css 后测试会指出哪一项不达标。
