# 0025 把 Humanize 的方法融入原生审查链，而非引入第二套任务系统

日期：2026-10-15。状态：候选实施；测试、独立审查、合入与生产加载分开记录。

## 背景

Humanize 的 RLCR 将计划/进度核对与真正的代码审查区分，BitLesson 将经验作为可选择、有证据来源的项目资料。ATW 已有独立工作副本、精确提交审查和发布门禁，不缺另一个拥有合并权的主控。

实际缺口：`bus_build_safety.review_pack` 只发差异和作者门禁，没有冻结的原始任务目标；`set_review` 覆盖最后结论，后续返修看不到前轮意见；历史教训散在长文档里，没有按本次改动选择。

## 决定

自主实现小型 `bus_review_context`，不复制上游代码或长提示词，不增加依赖，不安装 CLI/hooks，不新建插件进程、数据库或任务真值。

1. 在现有 `bus_core.dispatch(build)` 中，根据已校验的问题和上下文元数据生成 `review_brief`，由 `bus_build.open_worktrees` 保存在既有施工记录。带原问题、完整问题摘要、截断标志、有限来源摘要、项目/父任务和内容指纹。不重新读取笔记、不复制来源正文、不从自然语言猜出已获授权的结构化目标。
2. `render_task(build)` 在施工开始前按显式上下文路径选择经验；`review_pack` 带入原始目标，要求 Reviewer 分别报告 GOAL_COVERAGE 和 CODE_REVIEW，并注明实际证据与未知项；代码差异与精确提交仍由既有安全模块生成。计划看似完成、模型总结、CLI 成功退出均不等于 PASS。
3. 在既有审查写入锁内，且所有原有作者/提交检查通过后，保留最多八条历史反馈，送审最多显示最近三条；相同回执去重，省略计数明确。历史不是新的批准来源，不替代完整日志。连续退回只提示人工分析根因，不自动派工或无限运行。
4. 从工作台自己的源码目录读取受版本管理的经验目录，依据当前精确差异路径选择最多三条。条目必须 accepted、有合法且存在的本仓库测试引用；引用存在不代表本轮测试已通过。目录摘要、未选/无效状态一并呈现。

## 兼容与信任边界

旧施工单没有冻结目标时标记 unavailable，不能偷偷从后来可变的元数据推断原目标；旧调用 `open_worktrees` 不要求新增参数。修改已有任务意图需要显式新任务/修订流程，本次不新增覆盖冻结目标的接口。

摘要用于检测意外漂移，不是数字签名或授权令牌。JSON 引用边界及凭据形状检查不是语义提示注入沙箱。目标、历史意见和经验均为参考资料，不得扩大写入、合并或发布权限。经验目录损坏/不存在只给诊断，不伪造经验或测试结果。

`review == PASS`、`reviewed_commit == current_commit`、作者隔离、测试门禁及发布授权保持不变；新模块无合并、派发或外发能力。经验更新仍要走普通源码 PR，不接受 Agent 自动把个人猜测升级成已验证经验。

## 没有在本批实现

没有把整个 RLCR/`hmz` 当执行器，没有自动返修循环、总费用预算管理、跨进程工作流恢复、Goal Tracker 状态数据库或跨项目学习平台。反馈历史只是有上限的上下文投影，不是上述功能的替代品。

未来 `hmz` 适配器可作为独立执行插件：只接固定任务和隔离工作副本，回传 run_id、停止原因、候选提交及证据，不拥有 ATW 合并权。先验证目标平台和故障恢复，必须区分预算耗尽、进程退出、阶段答案与任务验收；不得把上游的终态直接映射为 ATW 已解决。未实现的插件不注册为空壳。

## 验证与回退

临时 Git 回归验证：原目标从派发进入送审；后改元数据不改变冻结目标；历史跨提交重放；重复回执不重复计数；过期或自审不写反馈；凭据形状不重广播；未获 PASS 仍不能合并；无目录及坏摘要明确降级；相关经验有界选择且测试未执行状态准确。

回退在独立分支创建逆向提交并复跑；旧版本忽略新增记录字段即可，不删除运行记录或改写历史，不自动重置任务。未改变旧页面交互，不重复要求用户验收原页面。
