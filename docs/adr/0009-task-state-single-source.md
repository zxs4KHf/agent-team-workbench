# 0009 任务状态的唯一真值是总线

**情况**：评估 `AgentWorkBench_Intake_0.1.0`（合并稿 `log/2026-09-26/20260926-142500-537c.merge.md`）时暴露出一个比"收不收这个包"更根本的问题：我们没有一条写死的规则说明**任务状态由谁说了算**。三家 Agent 的共识是，把那类"信息中枢"整装收进来，会一次性长出四套并行的东西：

| 维度 | 我们现有的 | 收进来会多出的 |
|---|---|---|
| 任务状态 | `projects/<slug>/decisions.json` + `inbox/ outbox/ log/` 文件队列 | `intake.sqlite3` |
| 编排 | `bus_dispatch` 多 Agent 对读 → `bus_collect` → 合并稿 | 三角色 jobs + 租约 |
| 前端与登录态 | 工作台 8765 + `console/mcp_token.txt` | 独立前端 8786 + `AWB_OWNER_TOKEN` |
| 调度循环 | `bus_guard` / Leader 的 wait 循环 | 它自己的 dispatcher 循环 |

只要出现第二个能写任务状态的地方，"这条任务现在到底什么状态"就不再有确定答案：两边都能改、两边都会落后、合并冲突只能靠人肉比对。合并稿的原话是：**"这条不定，后续所有集成都会跑偏。"**

**决定**：

1. **任务状态的唯一真值是总线**，具体是 `projects/<slug>/decisions.json`（结构化状态）加 `inbox/ outbox/ log/` 文件队列（过程与审计）。任何其它存储里的任务状态一律是**投影**，不是真值；投影与真值不一致时，以真值为准，投影重建。
2. **任何信息中枢只做两件事：来源采集、通知投递。** 采集 = 把外部世界的条目拿进来放进收件箱；投递 = 把总线已经发生的状态变化告诉人或外部系统。**两件事都不包括"决定任务处于什么状态"。**
3. **不得成为第二个 task 状态入口。** 判定标准很具体：这个子系统里有没有一张表/一个文件，它的字段能独立决定一条任务是 pending / running / done、能独立分配负责人、能独立判定完成？有，就是第二个入口。
4. **准入规则（将来任何子系统接入前，先回答这一题）**：
   - 问：**它会不会新增一个 task 状态入口？**
   - **会 → 不收**。可以收它的"模式"（做法、接口形状、并发口径），重写进我们自己的体系；不收它的状态存储与调度循环。
   - **不会 → 可以谈**，接入形态只有两种：作为**采集侧**（走 `plugins/<id>/` 子进程 + HTTP 送进收件箱，见 [PLUGINS.md](../PLUGINS.md)）或作为**投递侧**（消费 `events/YYYY-MM-DD.jsonl`，见 [0003](0003-events-outbox.md)）。
   - 这一题的答案要写进该子系统的接入记录里，不能默认通过。
5. 本 ADR 与 [0003](0003-events-outbox.md) 配套：0003 规定"跨系统同步只用只追加的事件记录"，本篇规定"事件的源头只有一个"。外部系统读事件、写收件箱，**不反向写任务状态**。

**为什么**：

- 双真值源的代价不是"多维护一份"，而是**任何一次不一致都要人来裁决**，而这个工作台的价值恰恰是减少人做非创造性的事。
- 我们的文件队列（`log/<日期>/`、`outbox/`）是人可读的审计资产，出问题用记事本就能查；SQLite 状态表没有这个性质。这一点三家 Agent 一致（合并稿共识第 6 条）。
- 把规则写成**一个可判定的问题**而不是一段原则，是为了让它在将来真的被执行——原则会被"这次情况特殊"绕过，判定题不会。

**放弃了什么**：

- 放弃了"直接整装接入成熟子系统"的速度。代价是每次接入都要重写一遍状态相关的部分。
- 放弃了 SQLite 事务带来的现成并发保证；我们自己的并发口径（`ws_write` 的 CAS、文件锁）要继续自己补（见 [ARCHITECTURE.md 的「借来的四条模式」](../ARCHITECTURE.md#借来的四条模式外部实现的经验不是外部的代码)）。

**范围限定（引用本篇时不要放大）**：本篇只定"任务状态"的归属。它不评价那个包的代码质量，也不构成对它的采纳或拒绝——处置结论是**(c) 起步：现在不装、不搬码、不改一行现有代码**，整包留档为参考实现与后续验收对象。

**回滚**：`git revert <本提交>`。本篇是纯文档，没有代码读取它；撤掉只会让准入规则回到"没有明文规定"的状态。
