# 0021 自动施工提交只接纳明确源码路径

日期：2026-10-14。状态：候选实施，独立审查与发布另行记录。

## 情况与决定

`commit_work` 曾执行无范围的 `git add -A`。在临时仓库复现：未被忽略的实例文件、已暂存运行数据会被提交；中间提交先加入再删除的私有路径会留在待合入历史中。

自动提交先检查工作区、暂存区和本任务基线后的中间提交，再用 NUL 分隔的精确字面路径暂存。已知运行目录、私有配置和凭据文件路径禁止新增/修改；允许删除旧误跟踪运行文件。新文件需属于明确源码类型与根目录，未知产物报错由操作者分类，不能悄悄忽略后宣称全部交付。中文和空格文件名保持原样。

缺少 Git 仓库的目录不再由 `ensure_repo` 自动初始化和整包提交。首次建仓必须成为明确的独立动作，既有有效 Git 仓库保持兼容。

## 边界与取舍

路径规则不是全面内容防泄漏系统。普通源码里嵌入的秘密仍需独立审查与发布扫描；不改写基线之前的历史。可信单用户、独占施工工作副本是前提，不承诺抵御恶意并发写文件/篡改 hooks。新格式、游戏资源或非标准源码目录需要显式扩展分类规则并测试，不能以忽略异常放行。

拒绝时不删除文件、不清暂存区、不移动分支、不生成成功施工回执。已忽略文件保持原样。Git 仓库定位环境不影响提交路径检查。普通人工提交仍须按项目审查规范执行。

## 验证与回滚

`tests/test_submission_scope_20261014.py` 使用一次性 Git 仓库验证边界、暂存区保全、历史检查、中文路径、正常源码、删除旧数据和未建仓目录无副作用。旧实现先复现失败，修复后复跑。

在独立回退分支撤销对应提交并重新验证；不清理任何真实运行目录，不把代码回退当作已经泄露历史的清理措施。
