# 0006 界面优化：先修"第一眼"，以实际渲染为准

**情况**：ArenaX 后端不再投入（本人 2026-09-28 决定），接下来只打磨界面。逐页截图（1440×900，浅色）后发现，最伤体验的不是"不够好看"，而是几处**一打开就错**的问题：
- 每次打开都落在一个空项目（0 条决策），地址栏 `?p=` 和上次的选择都被冲掉；
- 顶部一直挂着黄色"主控交接"警告，其实事情 40 多分钟前就恢复了；
- 设置页有零散的逗号、竖排的按钮文字、被挤断的标题、一张独占一行的卡片；
- 控制台有 duplicate id 警告（`#leaderBoard` 套在 `#leaderBoard` 里）。

**决定**：
1. 先修这类"一打开就错"的问题，每一处都有截图或代码行号作证据，不做凭感觉的整体翻新。
2. 默认项目 = **最近有动静的项目**（按决策最新的 updated/created），而不是列表第一个。只有当前项目不存在时才换；用户的选择和 `?p=` 优先。
3. 交接通知保持"常驻、手动关闭"的原设计（避免错过），但**事后已恢复的降为灰色**并写明现在由谁负责。判定规则：租约有持有人，且租约 epoch 比事件 epoch 新。
4. 界面统一用 **Leader**，不再混用"主控"。
5. 设置页固定两列：半宽卡两两成对，列表型卡片（服务守护）占整行，按钮文字不换行，原生文件框换成与按钮一致的样式。
6. 自带同 id 外壳的片段用 `morph(el, html, { outer: true })` 整体替换。
7. 820–1100px 这段宽度补上规则（原来只有 ≤820px 的手机布局）：顶栏只留图标、品牌文字隐藏、设置页单列。以"页面宽度不超过窗口"为验收，用脚本量，不靠目测。

**为什么**：画像里偏好"低认知负担、证据说话"。一个默认落在空项目的工作台，会让人以为数据丢了；一条永远黄色的警报会训练人忽略警报，这比没有警报更糟。

**放弃了什么**：
- 交接通知自动消失：会错过夜里发生的交接，所以不做。
- 设置页 auto-fit 自适应列数：宽屏上会出现 3 列和空洞，换成固定 2 列、窄屏（≤900px，沿用原断点）1 列。
- 动画、配色大改：没有证据表明它们是当前痛点，先不做。

**验证**：
- `tests/smoke_default_project_ui.mjs`（新）；
- `tests/smoke_lead_notify_2c14.mjs` 增加"已恢复 / 未恢复 / 无人持有"三种断言；
- 全量测试；
- 用线上数据加分支前端逐页截图，控制台无错误和警告。

**回滚**：`git revert <合入提交>`。只改前端和测试，不涉及数据和服务端。
