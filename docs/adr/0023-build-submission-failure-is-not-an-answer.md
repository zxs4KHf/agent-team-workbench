# 0023 施工提交失败不得归档为成功答复

日期：2026-10-14。状态：候选实施，独立审查与上线另行记录。

## 情况与决定

`bus_core.reply` 曾捕获 `commit_work` 异常，把“提交失败”写进答复头，然后继续写入正式 OUTBOX、删除领取文件、清除处罚并把成员标成 idle，最终返回 DONE。这会吞掉源码提交边界的失败，并失去正常重试入口。

施工提交抛异常或没有返回有效提交记录时，终止成功回执路径。原领取文件不改、不删除；答复草稿以随机标识保存到本机私有 `log/submission-failures/`，不能被 OUTBOX 答案收集器当作正式成果。向调用方报告失败与草稿标识，不回显原始异常细节。

草稿保存也失败时仍保留任务领取并明确报错，不假装保存成功。调用方修复问题后重试，只有提交成功才沿用原正常归档流程。

## 边界

不改变已有“代码已提交但测试门禁失败”送审语义，合入门禁仍须检查测试结果。此补丁不是整套 exactly-once 回复事务，也不改造所有历史回执；失败路径不重写领取数据，避免重新创建被另一成功请求删除的领取。

草稿仅留本机运行数据，不进入公共代码仓库。原始模型答复仍需按已有资料与隐私边界处理，不能将本机日志整包公开。

## 验证与回滚

`tests/test_build_reply_retry_20261014.py` 验证失败保留领取/草稿、没有成功 OUTBOX、没有 idle 心跳或清除处罚、提交记录缺失、原异常不外显，以及修复后可以重试成功。旧实现5项失败，修复后5项通过，全部使用临时目录与虚构提交结果。

独立回退分支撤销本补丁并测试后部署；不删除已保存草稿或原领取，不用强制归档解决失败。
