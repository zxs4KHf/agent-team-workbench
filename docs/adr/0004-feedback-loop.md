# 0004 体验反馈入口常驻每个页面，转任务由人触发

**情况**：你用工作台时遇到的不顺手，之前只能记在小米笔记或聊天里，之后很难回到工作台被处理（例如笔记里的"全局派发入口没了"）。你希望"体验问题能被记录，系统能自己迭代"。

**决定**：
- 每个页面右下角一个"反馈"按钮（Alt+B），写一句话即可；自动附带页面、视图、最后点击的元素、窗口尺寸。
- 反馈存本机 `feedback/`，状态：未处理 → 已转任务 → 已解决 / 不处理。
- "转成任务"由你点击触发，生成给 Leader 的指令：先复现、判断值不值得改；值得改按工作流施工，合入后标"已解决"并写提交号。

**为什么**：
- 记录的门槛必须极低（你的画像：非创造性的事一键完成），否则就不会记。
- 自动附带上下文，Leader 才能复现，不用来回问。
- 不自动转任务：防止随手一句话就启动一轮施工，浪费 Agent 额度。

**补充（2026-09-28，feat/feedback-ack-close）**：实测发现闭环最后一步是断的——指令要求 Leader「把反馈标为已解决」，但 Leader 只通过总线工作，11 个总线工具里没有改反馈状态的。改为：反馈转来的指令一经回执（`bus_console ack`），自动把反馈标为已解决（`ok=true`，回执说明写进备注）或不处理（`ok=false`）。不新增工具，因为 Leader 本来每条指令都必须回执。只动仍是「已转任务」的反馈（你手动关过的不覆盖）；关闭出错只记 `feedback.close_failed` 事件，不挡回执。
