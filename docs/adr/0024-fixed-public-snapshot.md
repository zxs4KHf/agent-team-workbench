# 0024 公开导出使用固定提交快照

日期：2026-10-14。状态：实施候选；合入、独立审查与公开推送分别记录。

## 问题

导出文档声称使用已提交文件，实际却用 git ls-files 配合工作区读取。已暂存或未提交的正文可能进入公开仓库；误跟踪的运行路径也没有不可放宽的排除边界。开发历史包含不宜公开资料，不能直接推开发仓库历史来完成公开同步。

## 决定

- 启动时将指定 ref 解析成一个 commit，之后只读该提交的树与 blob；导出策略也来自同一提交。
- 使用 Git 对象读取而非 checkout 或应用过滤器；清除可重定向仓库的 Git 环境变量，禁用替换对象。不读取工作区正文或暂存区，不修改源仓库。
- 强制排除已知运行目录、认证材料和本机配置，即使它们被误跟踪、导出配置忘记排除也不导出。配置可增加排除，不能解除强制边界。
- 选中范围中的符号链接、子模块、不兼容路径、大小写碰撞及超限对象明确失败。文件数、单文件与总大小有界；现有输出不覆盖。
- 隐私扫描作用于实际将导出的快照。应扫描文件不可读时失败，不把缺文件记为干净。明确指定的本机规则不可读或不存在时失败；未提供私有规则时清楚说明仅用了内置规则。
- 扫描输出只显示文件、行号与规则名称，不回显命中正文。本机规则不随快照导出。
- 公开快照不携带开发 Git 历史。既有公开仓库通过独立分支接纳快照并审查，保留其历史，不能强推覆盖。

## 取舍与边界

保留现有 exclude、scan_allow、generic_skip 的格式和测试语义，避免在此次重写整个隐私策略。规则扫描不是全面 DLP；扫描豁免文件、二进制素材、导出范围仍需发布方核对。不声称没有匹配就不存在敏感信息。不自动修改远端、发 PR 或部署。

## 验证

临时仓库覆盖工作区与暂存污染、历史 ref、脏策略、误跟踪运行文件、链接与子模块拒绝、文件冲突、环境重定向、摘要、缺扫描文件和不回显匹配。保留旧导出测试。实际公开准备先核对已认可的代码提交及素材，再在独立公开仓库分支处理。

## 回退

在独立分支撤销本实现并验证；不回写源仓库数据或改写远端历史。旧导出工具恢复后仍不得用于混有未提交内容的工作区。已公开内容的撤回是单独操作，不能靠本机代码回滚宣称已撤回公开副本。

## 审查返修与可运行检出

独立审查指出 feedback 等运行目录遗漏、豁免/二进制路径在扫描前未核实存在、最终导出允许既有空目录。均新增临时仓库回归并修复；正则错误统一返回导出失败且不回显规则。强制目录以本仓库运行约定为准，覆盖 profiles、workbench、锁与插件运行数据。

原始 Git blob 与可运行工作区不是同一层：BAT blob 可以是 LF，Windows 工作区必须按 .gitattributes 检出为 CRLF。新独立导出仓库提交成功后，仅移除本次在新目录生成且已纳入新提交的文件，再执行 checkout-index 以应用属性；不删除源仓库文件或任何既有用户输出。文件已落盘但 Git 认为 stat-clean 时，强制 checkout 仍可能不转码，因此用实际输出字节的失败/通过测试验证。

所有源文件摘要指原始提交 blob；公开提交的 blob 与源快照逐字节核对。工作区允许 Git 属性决定的换行变化，但不得让未提交正文进入公开历史。
