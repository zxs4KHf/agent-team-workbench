# 0013 派发模式与推进流程重做：三种派发、红队是角色、施工自动接上、你随时能补充

- 状态：提议（2026-10-01），等用户确认取舍后按阶段施工
- 来源：用户 2026-10-01 的整体反馈（「发起」页模式别扭、「挑毛病」不专业、施工是孤立的手动一步、超时太长、设置散落、页面难看）

## 现在是什么样（核实）

后端 `bus_core.MODES` 有 6 种模式，「发起」页直接把其中 4 种摆给用户：

| 页面上的名字 | 后端 mode | 实际是什么 |
|---|---|---|
| 方案讨论 | discuss | 每人独立写一份结论，Leader 合并——**其实不是讨论**，Agent 之间看不到彼此 |
| 独立作答 | independent | 每人独立写结论 + 理由 + 最强反驳，Leader 合并 |
| 专门挑毛病 | redteam | 给一份方案，每人找 3 个失败理由 |
| 接力补细节 | relay | 给一份骨架，Agent 在上面补，标 [新增]/[修改] |
| （不在发起页） | build / review | 施工 / 审查，由 Leader 在「采纳」后派 |

问题：① 讨论和独立作答几乎一样，真正的「讨论」（互相看见、互相回应）不存在；② redteam / relay 其实是「对一份已有材料做什么」，不是派发方式；③ 「抢单」不存在：派给 3 个人就是 3 个人都做；④ 讨论 → 采纳 → 施工之间每一步都要人点；⑤ 默认 30 分钟、派给几个人、用哪个团队等设置分散在页面底部。

## 决定

### 1. 派发方式只剩三种（回答「怎么分工」）

| 方式 | 行为 | 何时用 |
|---|---|---|
| **抢单** | 广播给选中的人；第一个领到的人做，其余人的副本立即撤回 | 一件事一个人做就够、要快 |
| **独立思考 + 汇总** | 每人独立作答（彼此看不到），到齐后 Leader 汇总共识 / 分歧 / 最终方案 | 要多个角度、防止从众 |
| **讨论** | 多轮：第 1 轮各自作答；之后每轮把上一轮所有回答发给每个人，让他回应、补充、修正；到轮数上限或 Leader 判定收敛就汇总 | 需要互相挑战、逐步收敛的问题 |

「抢单」实现：派发时照常给每人写副本；`wait_task` 领取时在同一把锁里检查「这单是抢单且已被别人领走」，是就把本人副本标为 `.json.taken_by_other` 跳过；第一个领到的同时撤掉其他人副本。复用现有收件箱，不新增队列。

### 2. 「红队」「接力」是附加在任意方式上的角色（回答「每个人做什么」）

- **红队**（替代「专门挑毛病」）：给某些参与者加「红队」角色——他的任务是找出方案会失败的具体场景、触发条件与后果，并给修改建议。可以「全部红队」也可以「3 人里 1 个红队」。与审查（review）区分：审查是对**代码提交**下 PASS / RETURN，红队是对**方案**做对抗。
- **接力补充**：讨论方式的第 2 轮起，或独立思考汇总后，可以「让 X 在 Y 的回答上继续补充」——把 Y 的回答作为材料发给 X，X 的补充标 [新增] / [修改]。
- 后端仍用 angle / role_line 承载角色，`MODES` 里的 redteam / relay 保留给旧数据与 Leader 直接调用，页面不再把它们当派发方式。

### 3. 推进流程：能自己走的就自己走，要你拍板的给推荐项

```
发起 → 回答到齐 → Leader 汇总（合并稿）
   ├─ 简单、无分歧、无需你决定 → Leader 直接采纳并派施工（自动）
   └─ 有分歧 / 有取舍 → 决策卡给 2–4 个选项，**标出推荐项与理由**，你点选或补充
采纳 → 施工（自动派 builder，按 ADR 0012 分配）→ 审查（自动派 Reviewer）→ 合并 → 通知你结果
```

- 「简单」的判定交给 Leader，但必须在合并稿里写一行「自动推进理由」；你在设置里可以关掉自动推进（默认开）。
- `decisions_needed` 的选项加 `recommended: true` 与 `why`，决策卡把推荐项放第一个并高亮。
- **随时补充**：每个进行中的任务都有一个「补充说明」输入框，提交后作为 `user_note` 追加给所有还没回答的参与者（已领取的人在下一次 ws 调用的返回里看到提示），并进入合并稿的输入。补充不是点按钮，是写字。

### 4. 「发起」页重做

- 顶部一行就是全部设置：方式（三选一）· 参与者（「全部在线」点一次全选、再点一次全不选）· 红队几人 · 最多等多久 · 至少几份；默认值：**等 10 分钟**（原 30）、独立思考默认 3 人、讨论默认 2 轮。
- 问题输入框占主体；附件、上下文文件折叠在输入框下面。
- 「派发」按钮固定在设置行最右，不用滚到底。
- 只用 tokens 与组件（ADR 0011 阶段 1 的 `btn()` / `chip` / `card`），不写内联样式。

### 5. 服务控制

设置页「服务」卡：工作台 8765、MCP 8791、守护、保活四行，每行状态 + 「重启」；顶部「全部重启」。复用已有的 `/api/admin/restart`（8765）与 MCP `/admin/shutdown`，守护 / 保活走 `bus_guard` 的拉起逻辑；重启 8765 时页面显示「重连中」并自动恢复（SSE 已会重连）。

### 6. Agent 分组编辑

现状：分组 = Arena 模型组（同组即同一模型），所以「新建 / 删除分组」与这个定义冲突。决定：
- 分组仍按模型自动归类，但允许**改显示名**、**折叠 / 展开**、**拖动排序**（修好现在拖不动的问题）、**置顶**（已有）；
- 另加**自定义标签组**（例如「主力」「备用」「红队池」）：可新建、改名、删除，一个 Agent 可以在多个标签组里；派发页的参与者选择可以按标签组一键选；
- Agent 卡片加「删除这个 Agent」（只删登记与收件箱里已过期的副本；手上还有单的先提示改派）。

## 分阶段（每段可单独合入、单独回滚）

1. 发起页：全选切换、默认 10 分钟、设置上移到顶部一行（纯前端，小）
2. 抢单方式（后端领取锁 + 前端选项）
3. 红队 / 接力改为角色；文案统一（「专门挑毛病」→「红队」）
4. 决策推荐项 + 随时补充
5. 自动推进（合并稿 → 采纳 → 施工），开关默认开
6. 讨论方式（多轮）
7. 服务控制面板
8. Agent 分组编辑与自定义标签组
9. 发起页视觉重做（与 ADR 0011 阶段 1 组件一起）

## 放弃了什么

- 保留 6 种模式都摆在页面上：用户已经明确说别扭；把「做法」和「角色」拆开后组合更多、选项更少。
- 讨论方式做成实时聊天室：Agent 是轮询领任务的，实时互聊做不到也不必要；按轮次推进可控、可回放。
- 自动推进一律不需要人：涉及取舍的决定必须由你拍板，系统只负责把选项和推荐理由摆清楚。
