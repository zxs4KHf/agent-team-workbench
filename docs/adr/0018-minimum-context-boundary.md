# 0018 派发前最小上下文与敏感内容复核

日期：2026-10-13。状态：已采纳为实施方向（本人授权）；实现以测试和审查记录为准。

## 当时的情况

数据源已有部分敏感关键词筛选，但原始材料与模型上下文仍有不同访问路径，不能仅靠上游筛选保证所有派发安全。

## 决定

新增集中上下文防护，在核心派发副作用前检查question和选定文件。对凭据文件、敏感运行目录、越界/符号链接逃逸、超限或不支持内容拒绝读取/派发，错误不回显正文或秘密。允许范围沿用工作区/已批准仓库，不能因为新增防护扩大读取范围。

内容含明确的常见凭据格式时拒绝派发，提示用户选择更小的安全摘录。上下文记录来源相对路径、大小和sha256；已有正常代码上下文保持兼容。材料用明确的数据边界标识，不得成为扩权指令；插件调用不能绕过核心检查。

此能力不是全面DLP、不是OS沙箱，也不能保证消灭语义提示注入。不要承诺自动识别所有私人数据或任意编码秘密。测试使用虚构样例，不检查真实账号有效性、不改密钥。

## 为什么与放弃了什么

最小化和拒绝危险内容优于静默将整份原始导出交给模型。放弃部分超大或含敏感配置文件的直接派发，保留按需安全摘录。

## 验收

虚构的JSON/URL认证信息、Bearer、私钥、会话格式；正常源码不误拦；错误不泄漏；路径/符号链接/编码/大小；失败时不创建meta/inbox；兼容选定文档与代码的现有结构。

## 回滚

revert独立功能提交；不删除原始材料、不改变凭据、不扩大既有workspace授权。保留被拒绝的记录摘要但不记录秘密。
